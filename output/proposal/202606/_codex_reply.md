## 현재 레이아웃의 문제점 (내 진단)

### A. Pyramid Principle 위반 — 결론보다 데이터가 먼저
- `종합 요약`이 차트 위주라 Executive Summary 역할을 못 함. 클라이언트가 첫 페이지에서 "6월에 우리는 무엇을 할 것인가"를 한 줄로 알 수 없음
- 모든 탭이 "데이터 → 토글에 숨긴 결론" 구조. 컨설팅 보고서는 "주장(So What) → 근거(Why)" 흐름

### B. 정보 위계 평탄화
- 탭 내부에 동일 레벨의 sec-lbl이 5~8개 나열됨 (`타겟팅·콘텐츠` 탭 8개, `6월 목표·액션` 탭 7개)
- 본문/부록의 구분 없음 → 핵심과 보조 자료가 시각적으로 동등
- 토글(`<details>`)에 핵심 정보가 묻혀 있는 반면, 부차 분석(라이프사이클 변주 가이드, 키워드 사분면)은 메인에 펼쳐 있음

### C. 타겟팅·콘텐츠 탭의 카오스
- 한 탭에 6개 분석 도메인(소재유형/동일소재변동/키워드/라이프사이클/OFF/지점별 추천)이 일렬로 쌓임
- 지점 필터가 중간에 sticky로 박혀 있고, 적용 범위가 모호함
- "6월 타겟팅·콘텐츠 리스트" 표가 그 모든 섹션 다음에 등장 → 클라이언트 핵심 요청 항목이 가장 뒤로 밀림

### D. 시각 위계 부족
- 카드들이 모두 비슷한 padding/border, 같은 폰트 사이즈
- 차트가 본문 중간에 들어가 호흡이 끊김
- 색 코딩(빨강/주황/초록)이 셀 단위만 적용, 섹션 레벨에서는 일관 안 됨

### E. Action ↔ Evidence 연결 미흡
- 6월 목표 → 그 목표 달성 액션 → 액션 검증 KPI → 액션의 근거 데이터 흐름이 분리됨
- 지점별 카드와 `funnel-action-matrix`가 같은 내용을 다른 형태로 두 번 보여줌

## 내가 생각하는 재구조화 방향 (피드백 요청)

### P0. Executive Summary (1page-look)
- 헤드라인 한 줄 ("6월 다이트한의원 운영의 핵심: [X]")
- Key Findings 3개 카드 (Pyramid 최상층) — 발견, 함의, 액션 한 줄씩
- Strategic Imperatives 3개 (6월 무엇을 할 것인가) — 효율 개선/예산 확대/신규 안정화 그룹별
- 6월 전 지점 합산 목표 (CPM/CTR/CVR) 미니 카드 3개
- 보조 차트 1개 (지점 전환수 막대 또는 4사분면)

### P1. 진단 (월별 지점 퍼널)
- **메시지**: "9개 지점을 3그룹으로 나누면 운영 패턴이 명확해진다"
- 상단: 9지점 × 3퍼널 약점 매트릭스 (○/△/✕) — 한눈에 보이는 진단
- 중단: 전환량 × CPA 사분면 차트 (지점 그룹화 시각화)
- 하단: 월×지점 히트맵 3개 (CPM/CTR/CVR) — 근거
- 부록: 지점별 절대값 표, 평균 대비 비교

### P2. 6월 목표 + 퍼널별 원인 분석·액션
- **메시지**: "퍼널별로 원인이 다르므로 액션도 달라야 한다"
- 상단: 6월 목표 카드 9개 지점 × 3퍼널 매트릭스 (핵심 결과물)
- 중단: 퍼널별(CPM/CTR/CVR) 원인 분석 카드 3개
  - 각 카드: 문제 지점 → 원인 가설 → 액션 → 검증 KPI
- 하단: A/B/C 그룹별 지점 액션 카드 (현재 디자인 유지)
- 부록: 4주차 로드맵, 요일별, 클라이언트 확인 요청

### P3. 타겟팅·콘텐츠 (가장 큰 재구조화)
- **메시지**: "지점별 약점 퍼널을 보완하는 타겟팅·콘텐츠 매트릭스"
- 상단: 6월 타겟팅·콘텐츠 통합 매트릭스 (지점 × 퍼널 → 타겟팅 방향 + 추천 콘텐츠 1~2개 + 새로운 시도)
- 중단: 지점별 콘텐츠 카드 (A/B/C 그룹) — 유지/확대/신규 도입
- 하단: 퍼널별 우수 콘텐츠 TOP3 (CPM/CTR/CVR 동등 노출)
- 부록 토글: 소재유형 / 신규vs재가공 / 키워드 사분면 / 라이프사이클 / OFF 분석 / 동일소재 지점간 차이 (이 6개는 부록)

### P4. 애드온 (현재 거의 OK, 정리만)
- 핵심 판단 카드 1개 (확대 / 유지 / 보류)
- 근거: 전체 차이, 지점별, 페어 비교
- 6월 실행 가이드 (제한적 A/B)

P0~P4 재구조화 방향은 맞습니다. 지금 필요한 것은 “더 많은 분석”이 아니라 **보고서의 논리 순서 재편**입니다. 컨설팅 보고서 형식으로 보려면 탭 구조를 데이터 카테고리 기준이 아니라 **의사결정 흐름 기준**으로 바꾸는 것이 핵심입니다.

1. **P0 종합 요약**: 6월 운영 의사결정 요약
2. **P1 성과 진단**: 지점별 퍼널 병목과 그룹화

**1. P0~P4 구조에 대한 의견**

전체 방향은 타당합니다. 특히 `타겟팅·콘텐츠` 탭에서 분석 자료를 부록으로 내리고, 실행 매트릭스를 상단으로 올리는 판단은 반드시 필요합니다.

다만 P0에는 “Key Findings”보다 **Management Decision** 성격을 더 넣는 것을 권장합니다.

현재 구상:

- Key Findings 3개
- Strategic Imperatives 3개
- 6월 목표
- 보조 차트

권장 구조:

- **6월 운영 결론 1문장**
- **3대 운영 판단**
  - 어디를 확대할 것인가
  - 어디를 효율 개선할 것인가
  - 어디를 신규 안정화할 것인가
- **지점 그룹별 방향**
  - A: 확대 운영
  - B: 효율 개선
  - C: 학습/안정화
- **전 지점 공통 목표**
  - CPM / CTR / CVR
- **가장 중요한 근거 차트 1개**

즉, P0는 “분석 요약”이 아니라 **클라이언트가 내부 보고에 그대로 쓸 수 있는 1-page executive memo**가 되어야 합니다.

P1은 진단 페이지로 적절합니다. 다만 `월별 지점 퍼널`이라는 이름보다는 **성과 진단** 또는 **지점별 퍼널 진단**이 더 좋습니다. 월별 데이터는 핵심 메시지를 뒷받침하는 근거이지 페이지의 주제가 아닙니다.

P2는 가장 중요한 페이지입니다. 현재처럼 목표, 액션, 로드맵, 요일별 운영, 확인사항이 모두 한 화면에 있으면 다시 평탄해질 수 있습니다. P2의 메인 영역은 아래 3개만 남기는 것이 좋습니다.

- 지점별 6월 목표
- 퍼널별 병목 원인
- 병목별 액션 및 검증 KPI

4주차 로드맵, 요일별 운영, 클라이언트 확인 사항은 부록 또는 하단 보조 영역으로 낮추는 편이 맞습니다.

P3는 지금 구조 변경의 핵심입니다. 클라이언트 요청의 4번 항목인 “타겟팅-콘텐츠 리스트업”이므로, 이 탭은 분석 리포트가 아니라 **운영 실행표**처럼 보여야 합니다.

P4 애드온은 현재 방향대로 간결하게 가면 됩니다. 단, 애드온은 독립 분석처럼 보이면 안 되고 “6월 운영안에서 어떻게 반영할지”까지 연결되어야 합니다.

| 추천 콘텐츠 | 기존 우수 소재 또는 재가공 소재 |
| 신규 테스트 | 새롭게 시도할 메시지/포맷 |
| 기대 개선 지표 | CPM 절감 / CTR 상승 / CVR 상승 |
| 검증 KPI | 1주차 판단 기준 |
| 운영 우선순위 | High / Mid / Low |

현재 데이터 기준으로는 다음 소스에서 끌어올 수 있습니다.

- `june_targets`: 지점별 CPM/CTR/CVR 목표
- `recommendations`: 지점별 운영 추천
- `action_table`: 실행 액션
- `top_creatives`: 퍼널별 우수 콘텐츠 TOP3
- `creative_type`: 소재 유형별 성과
- `keyword_analysis`: 키워드/메시지 방향
- `lifecycle`: 신규/재가공/반복 소재 판단
- `off_analysis`: OFF 소재 활용 여부
- `cross_variance`: 동일 소재의 지점 간 성과 차이
- `root_cause`: 원인 가설
- `conversion_perspective`: 전환 관점 보완

가장 중요한 것은 매트릭스의 셀을 너무 많이 채우지 않는 것입니다. 지점×퍼널 구조를 그대로 만들면 9×3 = 27셀인데, 각 셀에 장문을 넣으면 바로 깨집니다.

권장 방식은 **지점 1행 + 퍼널 3칸 요약**입니다.

예시 구조:

| 지점 | 진단 | CPM 액션 | CTR 액션 | CVR 액션 | 6월 콘텐츠 |
|---|---|---|---|---|---|
| 강남 | CTR 병목 | 고비용 타겟 제외 | 후기형 소재 확대 | 예약 CTA 강화 | TOP 소재 2개 + 신규 1개 |

각 퍼널 칸 내부는 다음처럼 짧게 제한합니다.

- `상태 배지`: 양호 / 개선 / 우려
- `액션 1줄`
- `추천 소재명 1개`
- `KPI 1개`

즉, 셀의 형식은 다음 정도가 적절합니다.

```text
CTR 개선
후기형 숏폼 확대
TOP: 소재 A
KPI: CTR 1.2%+
```

상세 근거는 하단의 우수 콘텐츠 TOP3와 부록 분석으로 내려야 합니다.

**3. 컨설팅 deck 스타일 디자인 디테일**

현재 다크 테마를 유지한다면 “대시보드” 느낌을 줄이고 “보고서” 느낌을 강화해야 합니다. 핵심은 카드 장식보다 **여백, 정렬, 제목 체계, 근거 구조**입니다.

권장 변경점은 다음입니다.

**페이지 헤더**

각 탭 상단에 고정된 형식의 header strip을 두는 것이 좋습니다.

```text
01 Executive Summary
6월 운영은 전환 가능성이 높은 지점 확대와 병목 지점 효율 개선을 병행해야 합니다.
분석 기간: 2026.02~2026.05 | 대상: 9개 지점 | 기준: TikTok Ads
```

이 구조가 있으면 페이지마다 “무슨 말을 하려는지”가 즉시 보입니다.

**섹션 번호**

섹션은 `1.1`, `1.2`까지는 좋습니다. 다만 너무 많으면 보고서가 딱딱해집니다.

권장:

- 탭 번호: `01`, `02`, `03`
- 섹션 번호: `1.1`, `1.2`
- 부록: `Appendix A`, `Appendix B`

**카드 위계**

모든 카드가 같은 톤이면 보고서가 아니라 컴포넌트 모음처럼 보입니다. 카드 등급을 나누는 편이 좋습니다.

- `Insight Card`: 핵심 주장, 강한 제목, 짧은 본문
- `Evidence Card`: 표/차트 중심, 톤 다운
- `Action Card`: 액션, KPI, 담당/시점
- `Appendix Card`: 회색 배경, 낮은 대비, 접힘 가능

**색상 규칙**

제안하신 색상 규칙은 좋습니다. 다만 다크 테마에서는 채도 높은 빨강/초록을 셀 배경으로 많이 쓰면 산만해집니다.

권장:

- 빨강: 우려/악화, 배경이 아니라 좌측 바 또는 배지
- 주황: 모니터링/주의
- 초록: 확대/양호
- 보라: 신규 테스트/관찰
- 회색: 부록/근거자료

셀 전체를 색칠하기보다 **상태 배지 + 얇은 border-left** 방식이 컨설팅 deck에 더 가깝습니다.

**폰트 위계**

권장 위계:

- 페이지 타이틀: 24~28px
- 페이지 메시지: 15~17px
- 섹션 타이틀: 16~18px
- 카드 타이틀: 14~15px
- 본문/표: 12~13px
- 메타/주석: 11~12px

다크 테마에서는 본문이 조금만 크거나 굵어도 답답해 보이므로, 표와 근거 영역은 더 작고 조밀하게 가는 것이 좋습니다.

**차트 사용**

차트는 줄이는 편이 맞습니다. 현재 보고서의 목적은 탐색형 대시보드가 아니라 의사결정 보고서입니다.

권장 차트 수:

- P0: 1개
- P1: 1~2개
- P2: 가능하면 없음, 표/매트릭스 중심
- P3: 없음 또는 TOP 콘텐츠 바 차트 1개
- P4: 1개

차트는 “근거를 직관화하는 장치”이지 페이지의 주인공이 되면 안 됩니다.

**4. 빌더 코드 변경 범위 권장**

통째로 갈아엎는 것은 비추천입니다. 현재 2,669줄 단일 템플릿이라도 이미 데이터 연결과 Chart.js 렌더링, 스타일, 탭 구조가 들어가 있을 가능성이 높기 때문에 전면 재작성은 회귀 위험이 큽니다.

권장 접근은 **페이지별 함수 분리 리팩토링 + 단계적 레이아웃 패치**입니다.

우선순위는 다음이 좋습니다.

1. **렌더링 함수 분리**
   - `render_executive_summary(data)`
   - `render_funnel_diagnosis(data)`
   - `render_june_action_plan(data)`
   - `render_targeting_content(data)`
   - `render_addon(data)`

2. **공통 컴포넌트 함수 추가**
   - `section_header(number, title, message, meta=None)`
   - `insight_card(title, finding, implication, action)`
   - `status_badge(status)`
   - `appendix_details(title, html)`
   - `metric_card(label, value, delta=None, status=None)`

3. **P3 타겟팅·콘텐츠 먼저 재구성**
   - 클라이언트가 직접 지적한 “깨짐” 영역
   - 핵심 요청 항목이 뒤로 밀린 문제
   - 가장 개선 체감이 큰 영역

4. **P0 Executive Summary 재작성**
   - 첫인상 개선
   - 보고서 전체의 논리 기준 확립

5. **P2 목표·액션 연결 강화**
   - 목표 → 원인 → 액션 → KPI 연결

6. **P1/P4는 정리 중심**
   - 기존 구조를 최대한 유지하되 제목, 순서, 부록화만 조정

즉, 코드 전략은 다음이 적절합니다.

```text
전면 재작성: 비추천
부분 패치만: 단기 가능하나 구조 문제 재발 가능
페이지별 함수 분리 + 핵심 탭 재배치: 추천
```

특히 지금은 HTML 자체보다 “보고서 구조”가 문제이므로, CSS만 만져서는 해결되지 않습니다. 반대로 전면 재작성은 데이터 매핑 오류 위험이 큽니다. 따라서 **렌더링 단위를 페이지별로 나누고, P0/P2/P3부터 재구성하는 방식**이 가장 현실적입니다.

**최종 권장안**

가장 먼저 고칠 곳은 `타겟팅·콘텐츠`와 `종합 요약`입니다.

- `타겟팅·콘텐츠`: 분석 모음 페이지에서 실행 매트릭스 페이지로 전환
- `종합 요약`: 차트 요약 페이지에서 의사결정 요약 페이지로 전환
- `6월 목표·액션`: 목표, 원인, 액션, KPI를 하나의 흐름으로 연결
- 나머지 분석은 “본문 근거”와 “Appendix”로 강등

보고서의 핵심 문장은 이렇게 잡는 것이 좋습니다.

```text
6월 운영은 전 지점 동일 최적화가 아니라, 지점별 퍼널 병목에 따라 확대·효율개선·신규안정화 전략을 분리 적용해야 합니다.
```

이 문장을 기준으로 P0~P4를 다시 배열하면, 클라이언트가 원하는 “핵심이 먼저 정리되고, 근거가 뒤따르는 완성형 보고서”에 훨씬 가까워집니다.

**결론**

P0~P4 재구조화 방향은 맞습니다. 지금 필요한 것은 “더 많은 분석”이 아니라 **보고서의 논리 순서 재편**입니다. 컨설팅 보고서 형식으로 보려면 탭 구조를 데이터 카테고리 기준이 아니라 **의사결정 흐름 기준**으로 바꾸는 것이 핵심입니다.

제가 권장하는 최종 구조는 다음입니다.

1. **P0 종합 요약**: 6월 운영 의사결정 요약
2. **P1 성과 진단**: 지점별 퍼널 병목과 그룹화
3. **P2 6월 목표·액션**: 목표, 원인, 액션, KPI 연결
4. **P3 타겟팅·콘텐츠 실행안**: 지점×퍼널별 실행 매트릭스
5. **P4 애드온 판단**: 확대/유지/보류 의사결정

현재 제안하신 방향은 컨설팅 deck의 기본 원칙인 **Answer First → Evidence → Action**에 부합합니다. 다만 몇 가지는 더 강하게 정리하는 편이 좋습니다.

**1. P0~P4 구조에 대한 의견**

전체 방향은 타당합니다. 특히 `타겟팅·콘텐츠` 탭에서 분석 자료를 부록으로 내리고, 실행 매트릭스를 상단으로 올리는 판단은 반드시 필요합니다.

다만 P0에는 “Key Findings”보다 **Management Decision** 성격을 더 넣는 것을 권장합니다.

현재 구상:

- Key Findings 3개
- Strategic Imperatives 3개
- 6월 목표
- 보조 차트

권장 구조:

- **6월 운영 결론 1문장**
- **3대 운영 판단**
  - 어디를 확대할 것인가
  - 어디를 효율 개선할 것인가
  - 어디를 신규 안정화할 것인가
- **지점 그룹별 방향**
  - A: 확대 운영
  - B: 효율 개선
  - C: 학습/안정화
- **전 지점 공통 목표**
  - CPM / CTR / CVR
- **가장 중요한 근거 차트 1개**

즉, P0는 “분석 요약”이 아니라 **클라이언트가 내부 보고에 그대로 쓸 수 있는 1-page executive memo**가 되어야 합니다.

P1은 진단 페이지로 적절합니다. 다만 `월별 지점 퍼널`이라는 이름보다는 **성과 진단** 또는 **지점별 퍼널 진단**이 더 좋습니다. 월별 데이터는 핵심 메시지를 뒷받침하는 근거이지 페이지의 주제가 아닙니다.

P2는 가장 중요한 페이지입니다. 현재처럼 목표, 액션, 로드맵, 요일별 운영, 확인사항이 모두 한 화면에 있으면 다시 평탄해질 수 있습니다. P2의 메인 영역은 아래 3개만 남기는 것이 좋습니다.

- 지점별 6월 목표
- 퍼널별 병목 원인
- 병목별 액션 및 검증 KPI

4주차 로드맵, 요일별 운영, 클라이언트 확인 사항은 부록 또는 하단 보조 영역으로 낮추는 편이 맞습니다.

P3는 지금 구조 변경의 핵심입니다. 클라이언트 요청의 4번 항목인 “타겟팅-콘텐츠 리스트업”이므로, 이 탭은 분석 리포트가 아니라 **운영 실행표**처럼 보여야 합니다.

P4 애드온은 현재 방향대로 간결하게 가면 됩니다. 단, 애드온은 독립 분석처럼 보이면 안 되고 “6월 운영안에서 어떻게 반영할지”까지 연결되어야 합니다.

**3. 컨설팅 deck 스타일 디자인 디테일**

현재 다크 테마를 유지한다면 “대시보드” 느낌을 줄이고 “보고서” 느낌을 강화해야 합니다. 핵심은 카드 장식보다 **여백, 정렬, 제목 체계, 근거 구조**입니다.

권장 변경점은 다음입니다.

**페이지 헤더**

각 탭 상단에 고정된 형식의 header strip을 두는 것이 좋습니다.

```text
01 Executive Summary
6월 운영은 전환 가능성이 높은 지점 확대와 병목 지점 효율 개선을 병행해야 합니다.
분석 기간: 2026.02~2026.05 | 대상: 9개 지점 | 기준: TikTok Ads
```

이 구조가 있으면 페이지마다 “무슨 말을 하려는지”가 즉시 보입니다.

**섹션 번호**

섹션은 `1.1`, `1.2`까지는 좋습니다. 다만 너무 많으면 보고서가 딱딱해집니다.

권장:

- 탭 번호: `01`, `02`, `03`
- 섹션 번호: `1.1`, `1.2`
- 부록: `Appendix A`, `Appendix B`

**카드 위계**

모든 카드가 같은 톤이면 보고서가 아니라 컴포넌트 모음처럼 보입니다. 카드 등급을 나누는 편이 좋습니다.

- `Insight Card`: 핵심 주장, 강한 제목, 짧은 본문
- `Evidence Card`: 표/차트 중심, 톤 다운
- `Action Card`: 액션, KPI, 담당/시점
- `Appendix Card`: 회색 배경, 낮은 대비, 접힘 가능

**색상 규칙**

제안하신 색상 규칙은 좋습니다. 다만 다크 테마에서는 채도 높은 빨강/초록을 셀 배경으로 많이 쓰면 산만해집니다.

권장:

- 빨강: 우려/악화, 배경이 아니라 좌측 바 또는 배지
- 주황: 모니터링/주의
- 초록: 확대/양호
- 보라: 신규 테스트/관찰
- 회색: 부록/근거자료

셀 전체를 색칠하기보다 **상태 배지 + 얇은 border-left** 방식이 컨설팅 deck에 더 가깝습니다.

**폰트 위계**

권장 위계:

- 페이지 타이틀: 24~28px
- 페이지 메시지: 15~17px
- 섹션 타이틀: 16~18px
- 카드 타이틀: 14~15px
- 본문/표: 12~13px
- 메타/주석: 11~12px

다크 테마에서는 본문이 조금만 크거나 굵어도 답답해 보이므로, 표와 근거 영역은 더 작고 조밀하게 가는 것이 좋습니다.

**차트 사용**

차트는 줄이는 편이 맞습니다. 현재 보고서의 목적은 탐색형 대시보드가 아니라 의사결정 보고서입니다.

권장 차트 수:

- P0: 1개
- P1: 1~2개
- P2: 가능하면 없음, 표/매트릭스 중심
- P3: 없음 또는 TOP 콘텐츠 바 차트 1개
- P4: 1개

차트는 “근거를 직관화하는 장치”이지 페이지의 주인공이 되면 안 됩니다.

**4. 빌더 코드 변경 범위 권장**

통째로 갈아엎는 것은 비추천입니다. 현재 2,669줄 단일 템플릿이라도 이미 데이터 연결과 Chart.js 렌더링, 스타일, 탭 구조가 들어가 있을 가능성이 높기 때문에 전면 재작성은 회귀 위험이 큽니다.

권장 접근은 **페이지별 함수 분리 리팩토링 + 단계적 레이아웃 패치**입니다.

우선순위는 다음이 좋습니다.

1. **렌더링 함수 분리**
   - `render_executive_summary(data)`
   - `render_funnel_diagnosis(data)`
   - `render_june_action_plan(data)`
   - `render_targeting_content(data)`
   - `render_addon(data)`

2. **공통 컴포넌트 함수 추가**
   - `section_header(number, title, message, meta=None)`
   - `insight_card(title, finding, implication, action)`
   - `status_badge(status)`
   - `appendix_details(title, html)`
   - `metric_card(label, value, delta=None, status=None)`

3. **P3 타겟팅·콘텐츠 먼저 재구성**
   - 클라이언트가 직접 지적한 “깨짐” 영역
   - 핵심 요청 항목이 뒤로 밀린 문제
   - 가장 개선 체감이 큰 영역

4. **P0 Executive Summary 재작성**
   - 첫인상 개선
   - 보고서 전체의 논리 기준 확립

5. **P2 목표·액션 연결 강화**
   - 목표 → 원인 → 액션 → KPI 연결

6. **P1/P4는 정리 중심**
   - 기존 구조를 최대한 유지하되 제목, 순서, 부록화만 조정

즉, 코드 전략은 다음이 적절합니다.

```text
전면 재작성: 비추천
부분 패치만: 단기 가능하나 구조 문제 재발 가능
페이지별 함수 분리 + 핵심 탭 재배치: 추천
```

특히 지금은 HTML 자체보다 “보고서 구조”가 문제이므로, CSS만 만져서는 해결되지 않습니다. 반대로 전면 재작성은 데이터 매핑 오류 위험이 큽니다. 따라서 **렌더링 단위를 페이지별로 나누고, P0/P2/P3부터 재구성하는 방식**이 가장 현실적입니다.

---

**최종 권장안**

가장 먼저 고칠 곳은 `타겟팅·콘텐츠`와 `종합 요약`입니다.

- `타겟팅·콘텐츠`: 분석 모음 페이지에서 실행 매트릭스 페이지로 전환
- `종합 요약`: 차트 요약 페이지에서 의사결정 요약 페이지로 전환
- `6월 목표·액션`: 목표, 원인, 액션, KPI를 하나의 흐름으로 연결
- 나머지 분석은 “본문 근거”와 “Appendix”로 강등

보고서의 핵심 문장은 이렇게 잡는 것이 좋습니다.

```text
6월 운영은 전 지점 동일 최적화가 아니라, 지점별 퍼널 병목에 따라 확대·효율개선·신규안정화 전략을 분리 적용해야 합니다.
```

이 문장을 기준으로 P0~P4를 다시 배열하면, 클라이언트가 원하는 “핵심이 먼저 정리되고, 근거가 뒤따르는 완성형 보고서”에 훨씬 가까워집니다.
